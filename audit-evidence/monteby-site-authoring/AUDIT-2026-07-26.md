# Monteby site-authoring mechanical pipeline audit

Date: 2026-07-26  
Scope: `monteby-site-authoring` source, installed-package surface, state-machine
reports, measured drafting, repair application, REST persistence, canonical
verification, and their automated tests.

## Verdict

**PASS — bounded mechanical pipeline.**

Within the declared resource envelope, the owned-HTML/live-page reconstruction
path no longer asks a model to invent a node map, select an alternate pipeline,
guess a section identity, summarize a partial queue, or subjectively declare
completion. The path is driven by versioned JSON artifacts, stable surface
identities, exact actions, typed live-contract controls, and hard gates.

This is not an unbounded promise for every possible document. Crossing a
declared bound, losing evidence, encountering an unexpressible contract
capability, or reaching ambiguous owned-content scope stops explicitly. It does
not truncate, approximate, or silently route to manual CSS.

## Critical findings and disposition

| Finding | Original failure mode | Disposition |
|---|---|---|
| Parallel unsafe pipelines | Extract/spec scripts, browser snippets, manual node maps, tolerance completion, credential examples | Removed from the installable skill and preserved only under `audit-evidence/monteby-site-authoring/rejected/`, outside the npm allowlist; the remaining `layout-kit` helper accepts only an environment-variable name, never a credential value |
| Partial complex pages | Caps were implemented with `slice()` and could silently lose bands, text, media, or repair items | Full evidence is retained inside explicit bounds; inputs above a bound fail before publishing layout/plan artifacts |
| Manual AUTHOR loop | A model had to interpret `repairQueue` and hand-edit builder JSON | `apply-layout-repair-queue.js` applies the complete queue atomically and emits the exact rerun |
| Unrelated regressions | A repair could rewrite passing sections | Before/after subtree SHA-256 proofs are required for every unrelated ROOT section |
| Unproven restore/delete identity | Filtered benchmark index could be mistaken for `ROOT.nodes` index | Static sections carry `data-monteby-node-id`; capture and benchmark propagate it; missing/ambiguous identity blocks deletion |
| Incomplete restore | A missing root could be restored without all descendants | Restore recursively copies the exact plan-owned subtree and rejects node-ID collisions |
| Plan trusted by shape only | Plan, candidate, contract, or captures could change after a pass | Plan source node-map digest plus file/node-map hashes bind plan, candidate, source/copied contract, and reference/target manifests; canonical verification recomputes every hash |
| False surface parity | Counts did not prove that each captured item became an authored node | Every text/media/group/child surface requires a stable `structureKey`, one mapping, an existing generated node, and ancestry below its planned Section |
| Weak graph audit | Cycles, orphans, multiple parents, duplicate edges, and children on leaves could survive | All graph classes are hard validation errors |
| Dead state transitions | Some failures immediately repeated the same command or routed every draft error to widget development | Retry actions carry an explicit resolved-condition gate; malformed/incomplete evidence and unknown failures are terminal `blocked_*`; only coded capability/control gaps route to product work |
| Non-canonical completion | Static render, partial capture, structural tolerance, or a green boolean could be mistaken for final fidelity | Only `run-canonical-verification.js` emits `DONE`; it requires exact saved-page scope, PHP HTML, three complete captures, immutable hashes, and explicit zero-diff evidence |
| Weak page scope | Same-origin URL or a JSON 2xx preview could be accepted without proving the exact WordPress page | Snapshot binds page ID to the authenticated WordPress core public link; save, preview, and canonical capture must use that exact URL; preview must contain rendered HTML |
| Unsafe persistence | Stale writes, blind conflict retries, or unsupported presentation overrides | Validate/save/preview bind one node-map SHA-256; PUT uses fresh `postModifiedGmt`; 409/428 never auto-retry; presentation is preserved by default and canvas atomically enables `disableGlobalTemplates` |

## Normative mechanical flow

```text
DISCOVER
  -> CAPTURE (desktop 1440, tablet 834, mobile 390; full page)
  -> PLAN (all bands and surfaces, hashes, no omissions)
  -> AUTHOR (generated draft or deterministic repair applier)
  -> LOCAL_VALIDATE
  -> LOCAL_RENDER
  -> LOCAL_COMPARE (zero configured screenshot budget)
  -> SNAPSHOT exact WordPress page
  -> REST_VALIDATE exact node-map hash
  -> versioned SAVE
  -> PHP_PREVIEW with rendered HTML
  -> FINAL_CAPTURE
  -> FINAL_COMPARE (complete explicit zero-diff proof)
  -> DONE
```

Every non-terminal report exposes exactly one `nextAction` object. A light model
needs only to parse the report, resolve whole-token requirements, execute the
ordered argv without a shell, and parse the next report. `complete` and
`blocked_*` actions have empty tool/args and are never executed.

## Declared completeness envelope

The generic measured path is complete, without sampling, for:

- at most 64 normal-flow page bands;
- at most 24 meaningful media surfaces in one band;
- at most 256 text surfaces in one band;
- at most 3200 CSS pixels of height for one band at any captured viewport;
- the exact canonical viewports `desktop:1440x1200`,
  `tablet:834x1112`, and `mobile:390x844`;
- components, props, enum values, controls, repeaters, and parent relationships
  authorable by the exact live contract.

Above those bounds the command emits a stable hard failure and writes no partial
plan. Mobile-only surfaces, missing stable keys, missing responsive controls,
unmapped nodes, and count mismatches are omissions and therefore cannot pass.

The screenshot comparison may neutralize only the interior pixels of
geometrically paired meaningful replacement-media boxes. Their existence,
count, role, bounds, crop geometry, edge pixels, overlays, shifts, and missing or
extra boxes remain enforced. Therefore `canonical_verified_1_to_1` means
one-to-one **layout and interaction fidelity under the declared media-content
mask**, not identity of third-party photography.

## Human decisions that intentionally remain

These are authorization or product decisions, not layout reconstruction work:

- ownership/license of source text and assets;
- approved legal/privacy copy and destinations;
- the exact owned-content scope of a non-duplicate extra band;
- development of a reusable capability absent from the live contract;
- reconciliation when another editor changes the page after snapshot;
- target site/page, authorization, rollback, and public-URL confirmation.

No model is authorized to guess any of them.

## Remaining external gates

- No real WordPress site was supplied for this repository audit, so the final
  network E2E depends on the target site's live Monteby endpoints and contract.
  The REST chain is covered by local integration servers.
- If canonical PHP markup does not expose a stable Monteby node ID for an extra
  band, automatic deletion is intentionally unavailable; the pipeline stops
  instead of inferring identity from geometry order.
- A layout outside the resource envelope or beyond the live component contract
  is a declared input/product boundary, not a partially supported success case.
